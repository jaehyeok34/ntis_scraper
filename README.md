## 프로그램 실행

### 1. jar 파일 실행

    명령프롬프트(CMD)를 실행하여 다음의 명령을 입력하여 jar 파일을 실행함

```bash
cd {RnD_Mail_Sender.jar 파일 경로}
java -jar RnD_Mail_Sender.jar
```

### 2. 수집된 공고에 학문 코드 수동 입력

    수집된 공고에 학문 코드 수동으로 부여하는 과정으로 공고의 제목이 먼저 출력되고, 학문 코드를 ‘, ‘(쉼표 + 공백)을 기준으로 입력 받음.

<aside>
⚠️

학문 코드 수동 입력 단계 주의사항

1. 일부 공고(domain.properties 파일에 명시되어 있는 공고)의 경우 자동으로 학문 코드가 입력되며, 수집된 모든 공고가 자동으로 입력된 경우 **해당 단계가 생략될 수 있음**.
2. 학문 코드를 수동 입력하는 과정에서 아무것도 입력하지 않고 enter를 입력할 경우 default 값인 45, 71, 77(산업공학, 과학기술, 기타공학)이 입력됨.
3. 학문 코드 입력 과정에서 ‘, ‘(쉼표 + 공백)을 기준으로 입력하지 않을 경우 오작동할 수 있음.
예시: 1, 2, 3(O) | 4,5,6(X) | 7, 8,9(X) | 1 2 3(X) | 123(△, 123번 학문 코드로 인식됨
</aside>

### 프로그램 종료

    모든 공고에 대해 학문 코드가 부여되면, 자동으로 receivers.xlsx의 내용을 기반으로 메일이 구성 및 전송 됨. 모든 메일이 전송되면 **자동으로 프로그램이 종료**되며, 컨펌 메일 혹은 전송 메일 계정을 통해 확인 가능함.

## 교수 정보 파일 관리

    receivers.xlsx의 기본 구조는 이메일, 연구분야, 전공분야, 관련교과목 컬럼으로 구성됨. 본 프로그램에서 이를 활용하기 위해서는 전공분야와 관련교과목을 기반으로 학문 코드를 부여해야 함. 현재(2026. 02. 19.) 기준 134명의 교수 정보에 대한 코드는 모두 부여된 상태이며 향후 교수 정보가 추가될 경우 전공분야 및 관련교과목을 기반으로 위 학문 코드 테이블에서 적절하게 부여해 줘야 함(수동 작업)

## 메일 수신자 그룹화 알고리즘 설명

### 시나리오

    수집된 공고 A, B, C, D가 있고, 이를 관심사로 등록한 교수가 1 ~ 5 있다고 가정하며, 다음과 같은 형태로 공고가 전달되도록 매핑된 상황이라고 가정.

| 교수명 | 매핑된 공고 |
| --- | --- |
| 교수1 | A, C |
| 교수2 | A, B, C, D |
| 교수3 | A, C |
| 교수4 | A |
| 교수5 | A, B, C, D |

<aside>
💡

관심사 등록

receivers.xlsx에서 교수의 전공분야 및 관련교과목을 기준으로 부여한 학문 코드를 의미하며, 수집된 공고 역시 게시자 혹은 수작업을 통해 학문 코드가 부여 됨.

이 둘을 비교하여 하나라도 포함되는 경우에 관심 공고라고 판단.

</aside>

### 초기 프로그램 메일 구조

   매핑된 공고의 중복과 상관없이 각 교수에게 개별적인 메일이 전송되도록 구성됨. 즉, 교수 1 ~ 5 각각 개별적인 메일이 작성되어 전송(메일 5건 전송) 됨.

❗️메일 수신 희망 교수의 수가 증가함에 따라 수집된 공고에 따른 수신 교수의 수가 증가하여 많게는 50건이 넘는 메일이 전송되는 상황이 발생함. ❗️

### 현재 프로그램 메일 구조

    매핑된 공고가 일치하는 교수는 동일한 메일 폼에 중복 수신자로 묶어서 메일을 구성함.

예시: 교수1과 교수3이 동일한 공고(A, C)에 매핑됐고, 교수2와 교수5가 동일한 공고(A, B, C, D)에 매핑됐기 때문에 이들을 그룹으로 묶어서 메일 구성 → A, C에 대한 메일 1건, A에 대한 메일 1건, A, B, C, D에 대한 메일 1건 총 3건으로 압축되어 전송됨.
